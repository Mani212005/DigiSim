# Hosting DigiSim: frontend on Vercel, backend on Render

Topology: static frontend on the Vercel global CDN, Flask backend as a Docker
container on Render. The browser never calls Render directly: `vercel.json`
rewrites every backend path to the Render host, so API calls stay same-origin
(which also keeps the `SameSite=Lax` session cookie working with no code
changes). The Azure Static Web Apps workflow is untouched and still deploys
the frontend to Azure as before.

The live deploy story is Vercel plus Render only. A minimal `netlify.toml`
(base `frontend/`, stock CRA build) exists solely to satisfy the Netlify
GitHub App's deploy-preview checks, which are required status checks on
PRs; no Netlify workflow, `_redirects`, or docs references exist, and no
traffic is served from Netlify.

## Backend on Render (click-through)

1. Push this branch / merge the PR, then open the Render dashboard.
2. **New -> Blueprint**, select the `DigiSim` repo. Render picks up
   `render.yaml` at the repo root, which defines one Docker web service:
   - Name: `digisim-backend` (image built from `backend/Dockerfile`,
     context `backend/`)
   - Plan: `starter` (the ML stack - torch/onnx/rapidocr - needs more than
     the free 512 MB; stay on `starter` or higher, not free)
   - Health check: `GET /health` (unauthenticated, defined in
     `backend/app.py`)
3. When prompted for the `sync: false` env vars, fill in:
   | Key | Value |
   |-----|-------|
   | `FRONTEND_ORIGIN` | `https://<your-app>.vercel.app` (only used for direct cross-origin calls; proxied same-origin calls skip CORS) |
   | `ROBOFLOW_API_KEY` | Roboflow API key for `/detect_gates` cloud inference |
   | `GEMINI_API_KEY` | Google Gemini key for `/api/circuit/photo-to-subcircuit` |
   | `JWT_SECRET_KEY` | auto-generated by Render (`generateValue: true`); keep it |
   Bypassed defaults already in `render.yaml`: `DETECTION_CONFIDENCE_THRESHOLD=0.35`,
   `MODEL_WEIGHTS_PATH=model/weights/best.pt`, `COOKIE_SECURE=1`.
   `PORT` is injected by Render automatically - do not set it.
4. Click **Apply / Create**. First build takes a while (torch + ultralytics
   wheels); the service is live when `/health` returns `{"status": "ok"}`:
   `curl https://digisim-backend.onrender.com/health`.
5. If you named the service anything other than `digisim-backend`, replace
   the `https://digisim-backend.onrender.com` destinations in `vercel.json`
   with your service URL.

### Model weights

Weights are never committed (`backend/model/weights/` is gitignored), so a
fresh deploy has no local YOLO weights:

- `/detect_gates` works immediately - it uses Roboflow cloud inference and
  only needs `ROBOFLOW_API_KEY`.
- `/detect_circuit` returns `503 pipeline_not_ready` until weights exist.
  Options: attach a Render persistent disk and upload `best.pt` there (then
  set `MODEL_WEIGHTS_PATH` to the disk path), or bake the weights into a
  private image build.
- The committed `backend/yoloe-11s-seg-pf.onnx` ships inside the image and
  backs the physical-board proposer path.

### Runtime notes

- Entrypoint: `gunicorn app:app --bind 0.0.0.0:$PORT --workers 1 --threads 4`
  (single worker - the ML stack is memory-heavy; scale the plan up before
  adding workers).
- CPU-only. There is no GPU expectation: torch runs on CPU, OpenCV wire
  extraction is classical CV, and onnxruntime uses the CPU provider.
- Free-tier services spin down when idle; the first request after sleep can
  take ~60s while the model stack loads. Use `starter` or higher to avoid
  spin-down for a live demo.

## Frontend on Vercel (click-through)

1. Open the Vercel dashboard -> **Add New -> Project**, import the `DigiSim`
   repo. Leave **Root Directory** at the repo root: `vercel.json` already
   sets the build (`cd frontend && npm ci --legacy-peer-deps && npm run build`)
   and output directory (`frontend/build`) for the `frontend/` CRA app.
2. Before deploying, add the environment variable:
   | Key | Value |
   |-----|-------|
   | `REACT_APP_API_URL` | `https://<your-app>.vercel.app` (your own Vercel URL - keeps calls same-origin through the rewrites) |
3. Click **Deploy**. Verify:
   - The canvas loads and SPA deep-links work (any route serves `index.html`
     via the catch-all rewrite).
   - `https://<your-app>.vercel.app/health` returns `{"status": "ok"}`
     (proxied to Render - proves the rewrites are wired).
   - Login/guest auth works (session cookie flows same-origin through the
     proxy; no cookie or CORS changes needed).
4. If the Render service URL differs from
   `https://digisim-backend.onrender.com`, update the rewrite destinations in
   `vercel.json` and redeploy.

## Local development (unchanged)

- Frontend: `cd frontend && npm install --legacy-peer-deps && npm start`
  (port 3000, `REACT_APP_API_URL` defaults to `http://localhost:5001`).
- Backend: `cd backend && uv sync && uv run python app.py` (port 5001).
